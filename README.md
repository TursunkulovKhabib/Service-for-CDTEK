# Контакты — микросервис справочника сотрудников (Django + AD/LDAP)

Микросервис забирает сотрудников из Active Directory, складывает их в PostgreSQL
и отдаёт наружу два REST API: **v1** — совместимый со старым Java/Servlet-сервисом,
**v2** — новый, с JWT. Данными будет пользоваться бот «Контакты» (MAX и Telegram) и
админка Django Unfold как справочник для поиска и ручных правок.

## Клиенты API

Логины старого API заводятся в админке: **Клиенты API**. Пароль хранится хешем,
права выдаются галочками по методам. Переменная `LEGACY_V1_CLIENTS` осталась только
для переезда: `manage.py import_api_clients` перенесёт логины из неё в базу.

## Фотографии

Снимок приходит из AD (`thumbnailPhoto`) и лежит на диске, а не в базе:
`<организация>/<UID из 1С>/{original,thumb,card}.jpg`. Уменьшенные форматы
создаются при первом обращении, снимок не растягивается сверх оригинала.
Каталог задаётся переменной `PHOTO_ROOT`, в Docker это том `contacts-photos`.
Пересобрать форматы после смены размеров: `manage.py rebuild_photos`.

Наружу фото отдаётся по адресу `/api/v2/employees/<guid>/photo/?size=thumb|card|original`,
в старом API это поля `photo` (thumb) и `photo_big` (card).

## Запуск в Docker

`docker compose up -d` поднимает пять контейнеров: `postgres`, `redis`, `app`,
`worker`, `beat`. Стек кладётся в Portainer как есть, переменные задаются в самом
стеке. Тестовые контроллеры домена вынесены в `docker-compose.dev.yml` и на сервер
не едут: `docker compose -f docker-compose.dev.yml up -d`.

## Персональные данные

Год рождения наружу не отдаётся ни в одном API — только день и месяц.
